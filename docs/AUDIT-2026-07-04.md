# Repository Audit — `abstraction`

**Date:** 2026-07-04
**Scope:** the full `abstraction` git repository — Python package (`abstraction/`), web app backend (`abstraction/app/`) and SvelteKit frontend (`frontend/`), test suite (`tests/`), CLI, packaging, scripts, CI, and repo hygiene. The legacy `abslithist/` and `abslithist2023-v2/` sibling directories were out of scope.
**Method:** five parallel deep-read audits (core pipeline; analysis layer; web app + frontend; infra/packaging/hygiene; tests) plus repo-level git checks. Every finding below was verified against source with file:line references; items marked **[verified by execution]** were reproduced by actually running code (crash repros, pickling repros, pyflakes, `find_packages`, a full pytest run, inspection of the ClickHouse directories).

---

## Executive summary

The scoring core that produced the current arc results is in good shape — the live ClickHouse scorer (`score_ids_ch`), the arc aggregation path, and the multilingual norms all work. But the repo is carrying real damage from its own rapid evolution: the JSON→DuckDB→ClickHouse migration and the IC-norms integration each left broken or stale paths behind, and the safety nets (tests, CI) rusted out without anyone noticing.

**Fix-first list (roughly in order):**

1. **The counting pipeline is broken today.** `get_contrasts()` crashes on the `IC.*` columns now present in allnorms, killing `count_absconc()`, passage generation, and `count-corpora` on any cold cache (§1.1).
2. **Every corpus-bias coefficient is attenuated** by a demeaning error in the estimator — the corpus-corrected numbers in the web app (and any book figures built on them) understate true bias by roughly (k−1)/k (§1.2).
3. **A fresh `pip install -e .` cannot run the web app** — `clickhouse-connect`, the primary datastore client, is not declared anywhere (§1.3).
4. **CI has been red since 2026-04-23 and 79 commits are unpushed.** 16 tests fail locally right now; the tests' norm-mocking contract has been silently dead since a cache-key change (§1.4).
5. **The web app has SQL injection and a path-traversal file read**, behind wildcard CORS with no auth, documented to run on `0.0.0.0` (§3).
6. **Several caches never invalidate on norm changes** — re-scoring after regenerating vecnorms can silently serve stale numbers (§4.1).

Beyond these, the report catalogs research-validity issues worth checking before book numbers ship (§2), a large dead-code/structure cleanup (§10), packaging fixes (§7), and improvement ideas (§12).

## 1. Critical — broken or bleeding today

### 1.1 `get_contrasts()` crashes on IC norm columns → counting pipeline down

`abstraction/norms.py:159` — `neg, pos = contrast.split("-")` assumes every norm column's contrast part contains a dash. The current `data.allnorms.pkl.gz` contains 22 `IC.*` columns (e.g. `IC.blbooks.C17`, `IC.Median.median`) whose contrast part is just `"IC"`. **[verified by execution]**: `get_allcontrasts()` raises `ValueError: not enough values to unpack (expected 2, got 1)`.

- **Blast radius:** `counting.get_norms_for_counting()` → `count_absconc()`, `count_absconc_psg()`, `count_absconc_corpus()`, `scoring.gen_bookpassages()`, and the `count-corpora` CLI command all crash on cold cache.
- **Why it went unnoticed:** `tests/test_counting.py:39-46` monkeypatches `_NORM_CONTRASTS`, hiding the production path; the 6 integration tests that *do* catch it (`tests/test_integration.py:182,238,249,256,266,342`) are excluded from CI and hadn't been run locally.
- **Fix:** in `get_contrasts`, skip columns whose contrast part has no `-` (or whitelist `Abs-Conc.*` prefixes). Add a unit test feeding `get_contrasts` a frame containing an `IC.Median.median` column — the exact crashing input.

### 1.2 Corpus-bias coefficients are systematically attenuated

`abstraction/corpus_correction.py:148-163` — the estimator demeans **y** within match groups (`gm["demeaned"] = score − group_mean`) but regresses on **raw** corpus dummies. For a 2-corpus group with true bias *b*, OLS recovers exactly *b/2*; in general coefficients are shrunk by roughly (k−1)/k for groups of size k (verified algebraically — `(X'X)⁻¹X'M_g Xβ ≠ β`).

- **Blast radius:** every value in `data/scores/corpus_bias_coefficients.json` (ecco +0.027, eebo_tcp +0.025, …) — consumed by the web app's corpus-corrected toggle and any analysis built on it. True biases are larger than reported.
- **Fix:** demean X within groups too (standard within-estimator), or fit `score ~ C(group_id) + C(corpus)` directly. Then regenerate the coefficients JSON and re-check any figures/prose that cite the corrected values.

### 1.3 Fresh install is broken: `clickhouse-connect` undeclared

`abstraction/app/db.py:20` imports `clickhouse_connect` **unconditionally at module top level**; also used at `cli.py:431` (`genre-tag-shift`), `cli.py:590` (`score-passages`), `aggregate.py:34`, and two scripts. It appears nowhere in `requirements.txt` or `pyproject.toml`. On a clean environment, `abstraction app` and two CLI commands crash with `ModuleNotFoundError`.

Other undeclared direct imports (all crash at call time on a fresh env — see §7 for the full dependency reconciliation): `openpyxl`/`xlrd` (all norm regeneration from Excel sources), `scikit-learn`, `umap-learn`, `statsmodels`, `matplotlib` (only transitively present via plotnine), `pydantic` (transitive via fastapi), `playwright` + `nest_asyncio`, and the `lltk` sibling repo (imported via `sys.path.insert` hacks).

### 1.4 Tests and CI have rotted — 16 local failures, CI red for ~10 weeks

Full local run (2026-07-04): **16 failed, 246 passed in 4:19**. GitHub CI: last run **2026-04-23, 37 failed / 192 passed / 2 skipped — and no runs since; 79 local commits are unpushed.**

Two root causes:

- **The `_NORM_DICTS` monkeypatch contract is silently dead.** `scoring.py:101-118` (`get_norm_dict`) now caches by tuple key `(col, lang)`, but tests patch string keys (`tests/test_scoring.py:35-38,461`, `tests/test_passages.py:36-40`, `tests/test_ci_integration.py:113,125,141`). Every lookup misses and the **real 2.58M-row allnorms is loaded from disk instead**. Consequences: 9 unit failures locally (fake-norm assertions vs real-data values); many other tests now "pass" only because real data happens to agree — false confidence; and in CI, where no data exists, 37 tests error, including `test_ci_integration.py` whose entire purpose is to run without local data. Fix by patching `get_norm_dict` itself (or tuple keys), owned by a single shared `conftest.py` fixture so the next signature change breaks one file, not four.
- **The IC-norms regression (§1.1)** accounts for the 6 integration-test failures.

Also: `tests/test_integration.py` has **no skip guards** — with the `/Volumes/chambers` data volume unmounted or `~/lltk_data` absent it produces an error storm rather than skips. There is no `conftest.py`, no pytest config, and no marker system; the unit/integration split lives only in the CI workflow's `--ignore` flag. See §6 for the full test audit.

## 2. Research-validity issues (numbers that could reach the book)

These don't crash; they quietly change reported quantities. Worth an explicit pass before Ch. 5 numbers are finalized.

1. **`report_full` labels count-based values with score-based decades** — `analysis.py:1933-1994` (and the prose block 2014-2047). Count percentages computed at the *count* analysis's key decades are printed in rows labeled with the *score* analysis's decades. Whenever the two fits pick different peak/trough decades (likely), the combined report attributes percentages to the wrong decades.
2. **The two "proportion abstract" measures silently disagree.** The count path (`analysis.py:1481-1502`) consumes histograms whose bin edges span only −3.0..3.0 (`scoring.py:1537,1572`), dropping |z| > 3 words from numerator *and* denominator, and its upper-edge keying implements strict `z < −1.0`; the live scoring path (`scoring.py:461-463`) uses inclusive, untruncated `v <= -cutoff`. `report_full` juxtaposes both as if commensurable. Fix: overflow bins + one boundary convention.
3. **`per_feature_r2` biases R² by feature prevalence** — `analysis.py:2396-2409` regresses without an intercept on centered X but *uncentered* y, systematically understating R² for high-prevalence binary features. This distorts exactly the feature ranking the function exists to produce (used in the embedding variance-partition analyses). Fix: center `v` before the lstsq.
4. **`norm_period` mislabels median-fallback texts** — `analysis.py:873-884`. Rows whose century score is NaN but whose year falls in a bin keep `norm_period="C18"` even though they were scored with the transhistorical median, contaminating period fixed-effect groups in the period-matched analyses. Fix: relabel to `"median"` wherever the fallback fills (and consider a `period_score_source` column).
5. **Mixed weighting in `report_arc`** — `analysis.py:694-712`: peak/trough decades are *selected* on corpus-balanced (decade, corpus) means but *magnitudes* are reported from text-pooled means; a decade dominated by one large corpus can report a magnitude inconsistent with why it was selected.
6. **German norms: Schmidtke supplement z-scored on its own subpopulation** — `norms_de.py:100-105` mixes two incompatible z-scales inside one `Abs-Conc.SCM-Imag` column. Fix: z-score the union once.
7. **`remove_stopwords=True` means different things per language** — EN filters the full 180K stopwords+names list with lowercasing (`norms.py:140-144`); FR/DE/ES filter only ~200 NLTK stopwords without lowercasing (`norms_fr.py:87-89`, `norms_de.py:117-119`, `norms_es.py:105-107`). EN scores exclude honorifics/names; the other languages keep them — a comparability caveat for the multilingual replication.
8. **Passage rendering silently deletes colons, quotation marks, and parentheses** — `tokenize.py:93` (via `passages.py:115`): the `tokenize_agnostic` regex has no class for `:`, `"`, `(`, `)`, so rendered HTML — used for the book's print passage figures and the web app passage view — drops them. Fix: pass unmatched characters through as punctuation tokens in the display path.
9. **`plot_norms` figures are not reproducible** — `plotting.py:111-113` uses unseeded `.sample(n=1)`; regenerating a book figure produces different example words each run. Add `random_state=`.
10. **The current CH/DuckDB scorers omit the `_pct_abs/_pct_conc/_pct_absconc` frequency-proportion columns** that the legacy JSON path computes (`scoring.py:511-577` and `:580-704` vs `:445-467`) — re-scoring via the live path silently loses a metric CLAUDE.md lists as a key concept.
11. **Boundary inconsistency at z = ±1.0** — fields/`classify_word` use inclusive `z <= −1 / z >= 1` (`norms.py`), passage CSS classes use strict `< / >` (`passages.py:45,55`), and several call sites hardcode ±1.0 instead of `config.ZCUT` (`scoring.py:266-275`, `counting.py:45`). A word at exactly ±1.0 is "Abstract" in the fields but "neither" in rendered passages.
12. **Three sign conventions coexist** (positive=concrete in `classify_word`, positive=abs in `_binz`, positive=abstract in `passage_abstractness_by_lang(invert=True)`). Each locally correct; the mix invites sign errors. Document or unify naming.
13. *(Idea, not a bug)* **Post-selection inference:** piecewise breakpoints are chosen by max-R² grid search, then slope p-values are computed as if the breakpoint were fixed (`analysis.py:479-492`) — they overstate significance. A bootstrap over (decade, corpus) bins would make the headline piecewise statistics defensible; at minimum note it in report output.

## 3. Security (web app)

Context: a localhost research app — but it ships wildcard CORS, no auth, and a documented `--host 0.0.0.0` option (`cli.py:941`), which makes these network-exploitable in practice.

1. **SQL injection via `col`** — `app/routes/arc.py:35,86,133,206,229,271,367,385,566`; `decompose.py:283-291,305-309`; `meta.py:70`. The user-supplied `col` param is f-string-interpolated into ClickHouse SQL (`f'"{col}" IS NOT NULL'`) with no allow-list. `?col=x" UNION ALL SELECT ... --` reads any table on the CH server (`lltk.*`, `system.*`).
2. **SQL injection via `genre`/`corpus` values** — `arc.py:336-337,371,385,547,568-599`; `decompose.py:272,291,309`: `WHERE {filter_col} = '{g}'` and unescaped `IN (...)` joins. Note `meta.py:54-56` already does this *correctly* with `?`-params — the safe idiom exists in the codebase; apply it everywhere, plus validate `col` against the known norm-column set.
3. **Path traversal → local file disclosure** — `trajectory.py:157-177` and `passage.py:67` pass a `{text_id:path}` URL segment into `corpus.read_text()` / `glob.glob(f"*{text_id}*")` (`corpus.py:41-46`), so `..` sequences survive and the passage endpoint returns raw file contents. `GET /api/passage/<corpus>/../../../../path/to/file/x/0` reads arbitrary `*.txt` files (the glob branch relaxes even that suffix). Fix: reject separators/`..` or resolve and assert containment in `corpus.path/txt`.
4. **Wildcard CORS + no auth** — `app/__init__.py:31-36` (`allow_origins=["*"]`, all methods/headers). Any website the user visits can call the API from their browser; on `0.0.0.0`, anyone on the LAN can. Restrict to known frontend origins and/or bind localhost + token.
5. **Hardcoded CH credentials in 5+ places** — `app/db.py:26-29`, `aggregate.py:24-27`, `cli.py:455-456`, `scripts/migrate_scores_to_ch.py:27`, `scripts/score_serverside_ch.py:30` (all `localhost:8123`, `lltk`/`lltk`). Low blast radius but should be a single factory in `config.py` reading `ABSTRACTION_CH_*` env vars.
6. **No query/connection timeouts** — `db.py:136-141`: a slow or injected heavy query blocks a FastAPI worker thread indefinitely. Set client timeouts + server-side `max_execution_time`.
7. **`/arc/print` race + unbounded input** — `arc.py:705-825`: every call renders to the same `data/figures/arc_print.png` and `FileResponse`s it; concurrent requests can serve one client another client's plot. Also accepts an arbitrary unbounded `list[GenreArc]`. Use unique temp files; bound the payload. Similarly `POST /passage/score` (`passage.py:117`) accepts unbounded text with no length cap.

## 4. Silent-corruption and stale-data hazards

1. **Score caches never invalidate on norm changes.** `freqs_cache.db` is keyed only by `(relpath, modernized)` (`scoring.py:27,1197-1217`) — after regenerating vecnorms/allnorms, `score_arc_corpora` silently returns scores computed under the old norms. The web app's on-disk trajectory cache (`trajectory.py:19-34,300`) has the same problem across `--refresh`. Fix: stamp caches with an allnorms fingerprint (hash of columns + mtime) and self-invalidate — one `norms_version()` helper covers `freqs_cache.db`, `_NORM_DICTS`, `_NORMS_ARRAYS_CACHE`, and the trajectory cache.
2. **Cross-language score contamination.** `_get_norms_arrays()` (`scoring.py:384-402`) is a keyless global cache: score English, then call `score_corpus_freqs(dir, allnorms=get_allnorms_fr())` — the documented multilingual entry point — and French texts are scored against **English** arrays with no error. Key the cache by the allnorms object.
3. **English-norms fallback is silent (and slow).** `get_norm_dict()` (`scoring.py:114-117`) silently falls back to English for missing non-English columns — `score_psg(txt, lang="es")` produces plausible-looking garbage — and never caches the fallback, so every call re-reads the full allnorms pickle from disk. Warn/raise, and cache under the requested key.
4. **Resumable CSV append under a stale header.** All three CSV scorers (`scoring.py:932-937,1121-1125,1495-1499`) skip `writeheader()` when the file exists but build `DictWriter` from the *current* column set — if norms changed between runs (e.g. IC columns added), appended rows are silently misaligned with the old header. Read and reuse (or refuse on mismatch) the existing header.
5. **Gzip files counted as raw text.** `count_absconc_path()` (`counting.py:126-131`) opens the `.gz` binary with `errors="ignore"` whenever no plain-text sibling exists — exactly the case where `corpus.text_path()` returns the `.gz` path. Gz-only corpora are "counted" over mojibake, silently yielding near-zero recognized tokens. Use a gzip-aware open (mirror `models.save_skipgrams_from_paths:64-70`).
6. **NaN years binned as pre-1500.** `_biny` (`scoring.py:283-284,297`) sends NaN to the 1400 bin, so undated texts appear as early texts in `get_all_passages`.
7. **`_try_merge` "most rows wins" can silently duplicate texts** — `analysis.py:212-256`: a lossy ID normalization producing a many-to-many join *inflates* the row count and therefore wins. Validate the winning merge is 1:1 (and log which strategy won — currently completely silent).
8. **`score_ids_duckdb` crashes on duplicate input ids** (PRIMARY KEY + plain INSERT, `scoring.py:653-657`), has no try/finally around its connection/temp tables, and its fixed temp-table names collide across concurrent calls on a shared connection (the "unique table names" comment at `:644` is wrong).
9. **`save_bookpassages` uses index labels as positions** (`scoring.py:337-355`): on any sorted/filtered df — e.g. the output of `count_absconc_psg`, which sorts — the final partial stack is silently dropped or flushed early.
10. **`aggregate.py:219` LIKE-pattern bug**: the leading `_` in `LIKE '_{corpus}/%'` is a single-char wildcard, and corpus names aren't LIKE-escaped. Use `startsWith(...)`.
11. **ClickHouse `FINAL` inconsistency** — `analysis.py:2339-2353`: `lltk.texts` is fetched `FINAL` but `abstraction.passage_scores` and `lltk.passage_embeddings` are not; unmerged ReplacingMergeTree parts would silently duplicate passages and inflate n in the variance-partition notebooks. (Same class of concern: reps with no scored group members vanish via INNER JOIN in `aggregate.py:181` with no accounting.)
12. **`words.py` crashes/misaligns on duplicate allnorms index** — `words.py:192-213` (shape-mismatch ValueError) and `:286-318` (reindex error). Duplicates demonstrably occur — `scoring.py` defensively dedups in nine places; these two functions are the only consumers that don't.

## 5. Crashes and functional bugs

**Parallelism that doesn't work:**
- `gen_skipgrams_corpus(num_proc>1)` **always crashes** — the nested closure `_do` isn't picklable under `ProcessPoolExecutor` **[verified by execution]**. Wired to `abstraction train-skipgrams --workers N` (`models.py:106-109`, `cli.py:352`). Same defect in `counting.py:166-178` (`incl_psg=True` path).
- `gen_vecnorms(num_proc=...)` accepts and **ignores** `num_proc` (`models.py:365`) — `abstraction gen-vecnorms --workers N` is a silent no-op.
- `pmap` returns results in input order serially but arbitrary (`as_completed`) order with `num_proc>1` (`corpus.py:80-89`) — latent footgun; current callers ignore return values.

**CLI:**
- `abstraction score-missing` writes to the **dead** DuckDB shadow (`scoring.py:707-889` → `scores_db.write_scores` → `scores.duckdb`), which nothing has read since the 2026-04-19 CH cutover — hours of scoring can land in an unread store while CH stays stale. Rewire to `score_ids_ch` or remove. Contains dead `... if False else lltk.db.read_freqs(...)` debug code at `:819-822`.
- `genre-tag-shift --invert` is a no-op flag (`cli.py:912-914`: `store_true` with `default=True`); only `--no-invert` does anything. Use `argparse.BooleanOptionalAction`.
- Language coverage is inconsistent: `score-ids`/`gen-vecnorms` accept `es`, but `score-missing` (`cli.py:790`) and `score-passages` (`cli.py:924`) stop at en/fr/de despite `norms_es.py` and `aggregate.LANG_TABLES` supporting Spanish; `corpus_correction._LANG_BIAS_FILES` (`:268-272`) also omits es.
- Stale help text references a different external volume (`/Volumes/diderot/...`, `cli.py:845`).

**Reports & plotting:**
- `int(NaN)` on piecewise breakpoints kills whole multi-genre reports (`analysis.py:815,1667,1799,1912,2198`) — one thin genre crashes everything; guard with `np.isfinite` as `summarize_arc` does.
- Rise/Fall direction words are hardcoded (`analysis.py:1978-1993,1664-1666`) — a genre whose concreteness moves the "wrong" way is still reported as "decline"/"increase".
- `plot_fiction`'s `min_y` compression is self-defeating: compressed values remain below `min_y`, so `p9.ylim` **drops those points entirely**; a second y-scale then replaces the limits, and the warning that would have exposed it is suppressed by `plotting.py:7-8`'s module-level `warnings.filterwarnings("ignore")` — which also mutes every pandas/numpy/scipy warning **process-wide** for anything that imports `abstraction.plotting`. (Also: `p9.options.dpi = 300` global side effect at import.)
- `facet_by_genre` crashes with `KeyError: None` when `color_col=None` (`plotting.py:791-795`); `_savefig` defaults to cwd-relative `"../figures"` (`:735`) — use `PATH_FIGS`; `quantile` on empty subsets yields NaN color bounds in the UMAP plots (`:841,900`).
- `_genre_from_title` `startswith` matching produces false positives (`analysis.py:117-125`): "talent(s)" → tale → Fiction.

**words.py:**
- One constant-trajectory word NaN-poisons the whole `correlation_z` column under Pearson (`words.py:244`, scipy `zscore` without `nan_policy`).
- Default `method="cosine"` on non-centered all-positive frequency trajectories measures *level*, not co-movement, yet the column is named `correlation` (`words.py:216-221`). Center first (making it Pearson) or default to Pearson.
- `freq_change_pct` with `clip(lower=1e-10)` produces ~10¹²% figures for words absent early (`words.py:334`).

**utils/tokenize/counting (smaller):**
- `read_df` dispatches on substring — `"foo.csv.pkl"` is read as CSV (`utils.py:19-33`); use `endswith` ordered by specificity as `save_df` does.
- `download_tqdm` progress bar off by 32,768× (`utils.py:85` — byte total, chunk-count updates).
- Off-by-one `tok_i` in the final partial counting window (`counting.py:120`); `get_norms_for_counting(sources={"PAV-Conc"})` silently returns `[]` for anything outside `SOURCES_FOR_COUNTING` (`counting.py:27-38`); `count_absconc_psg` double-passes `window_len` if a caller supplies it (`counting.py:143-146`); corpus CSV header drops the `num_words`/`num_tokens`/`tok_i`/`contrast` fields via `extrasaction="ignore"` (`counting.py:195-200`).
- `get_stopwords(use_nltk)` caches the first call's result regardless of the flag (`tokenize.py:40-57`).
- `StreamingSkipgrams._count_lines` raises `NameError` on an empty file (`models.py:155-160`); `periodize` breaks for years < 1000 (`models.py:387`); `_restrict_keyed_vectors` leaves gensim vecattrs misaligned (`models.py:277-289`, safe today only by luck of ordering).
- Playwright fallback only catches `ImportError`, so installed-but-no-browser raises instead of falling back to wkhtmltoimage; `save_comparison_image` has no fallback at all; `asyncio.get_event_loop()` is deprecated (`passages.py:307-395,503-528`).
- Post-CH-cutover DuckDB SQL against LLTK (`DESCRIBE texts`, `match_db.match_groups`, `texts.path_freqs`) at `scoring.py:1452-1461` and — **unguarded** — `corpus_correction.py:59-65`: re-running `estimate-corpus-bias` will likely fail or misbehave.

## 6. Tests & CI

**State:** 16/262 failing locally (see §1.4 for root causes); CI red since 2026-04-23; 79 unpushed commits; no `conftest.py`, no pytest config, no markers. `pytest-timeout` not installed.

**Coverage gaps (verified by grepping test imports):** zero tests for `aggregate.py` (280 lines — the arc dedup logic), `models.py` (445), `norms_fr/de/es.py`, `llm.py`, `scores_db.py`, and the **entire web app** (`app/db.py`, `db_compat.py`, `app/models.py`, all five route modules — including `decompose.py`'s Oaxaca-Blinder math, which is pure and eminently unit-testable). Near-zero: `analysis.py` (2,433 lines / 54 functions; only `assign_period_score` touched), `plotting.py` (only `_compress_year`), `cli.py` (3 of 21 subcommands).

**Quality issues:**
- Tautological assertion at `test_ci_integration.py:93` (ternary parse makes it always-true).
- Autouse cache-clear fixtures clear `_NORMS_ARRAYS_CACHE` but not `_NORM_DICTS` — the cache actually used — so real-data entries persist across the session (order-dependent tests) (`test_scoring.py:23-28`, `test_ci_integration.py:18-27`, `test_pct_scoring.py:12-16`).
- `test_force_flag` never exercises `--force` (`test_scoring.py:369-381`); mtime+sleep flake pattern in `test_cli.py:112-129`; `_make_fake_allnorms` and norm-patch helpers duplicated across 4 files; dead fixture `tests/fixtures/stopwords.txt`; PIL import inside the playwright test would `ImportError` rather than skip.

## 11. Performance

- **App endpoints pull unbounded result sets into Python** — `arc.py:83-89,115-137,368-387,568-599` SELECT every matching row (tens of thousands) with no LIMIT and do decade bucketing in Python that ClickHouse could do in one `GROUP BY` with `quantile()`/`avg()`. Push aggregation into SQL; this is also the back-pressure fix.
- **N+1 in `list_corpora`** — one `SELECT DISTINCT genre` per corpus (`meta.py:37-63`); replace with a single `GROUP BY` + `groupUniqArray`.
- The frontend `texts` page requests `page_size=10000` once, sorts client-side, and silently truncates bins with more rows (`frontend/src/routes/texts/+page.svelte:20-47`).
- **After each corpus, the entire output CSV is re-read** into a dict even when the CLI discards it (`scoring.py:1143-1145,1521-1524`) — heavy at 80K rows × 200 cols.
- `count_corpus_freqs` rebuilds a set comprehension inside `any()` — O(n_existing × n_new) (`scoring.py:1691-1694`); and `needs_update is not None` is always True.
- The `get_norm_dict` fallback path re-reads the full allnorms pickle **on every call** (§4.3).
- Failing integration tests burn 14-20s each re-loading the 2.6M-row allnorms — a session-scoped fixture would cut suite time substantially.
- `sys.path.insert` repeated on every call site grows `sys.path` unboundedly in long processes.
